왜 Narani인가

코드만이 아니라 의도를 함께 다룬다

에이전트가 만든 결과뿐 아니라 "왜·무엇을·어떻게"가 팀과 도구 사이에 그대로 흐릅니다.

4계층 컨셉 그래프

컨셉 → 도메인 → 컴포넌트 → 구현. 각 노드에 why/what/how/입출력을 담아 코드의 의도를 지도로 만듭니다.

팀 에이전트 피드

팀원의 에이전트가 한 작업이 git으로 공유됩니다. 엔트리는 파일 1개라 머지 충돌이 없습니다.

통합 마켓플레이스

Claude·Codex·Gemini의 스킬·MCP·플러그인을 한곳에서. URL이나 GitHub 저장소로도 바로 설치합니다.

코드 스페이스

Monaco 편집기와 터미널이 내장된 작업 공간. 문법 강조·자동완성으로 바로 보고 고칩니다.

내장 코드 인덱스

심볼·정의·참조를 결정적으로 찾아주는 코드 인덱스가 항상 켜져 있어, 파일을 통째로 읽지 않아 토큰을 아낍니다.

공식 프로토콜 연결

비공식 파싱이 아니라 Claude Agent SDK·Codex app-server·Gemini ACP 같은 공식 경로로 안전하게 붙습니다.

나란히(Narani) —
옆에서 함께 일한다는 뜻

에이전트에게 일을 던지고 결과만 받는 방식은 빠르지만, 팀과 코드의 맥락이 사라집니다. Narani는 사람과 에이전트가 같은 지도를 보며 일하도록 설계됐습니다.
